# 의류 쇼핑몰 FAQ 데이터

이 폴더의 쇼핑몰 규칙, 고객 이름, 주문, 문의는 상담 화면을 시연하려고 만든 가상 자료입니다. 실제 업체의 정책이나 거래를 복사하지 않았습니다. 실제 고객 정보, 법적 권리, 상담 실적을 나타내지 않습니다. 화면에서도 가상 의류 쇼핑몰임을 표시하며 고객 문의 본문에는 이 설명을 반복하지 않습니다.

## 파일 구성

- `documents.json`: 출고·배송, 사이즈 교환, 반품, 주문 취소, 불량·오배송, 배송비, 환불, 옷 관리, 배송 조회, 상담 기준을 다룬 FAQ 10개입니다. 구조는 `{id, title, topic, version, body}`이며 최초 버전은 1입니다.
- `customers.json`: 고객 6명의 주문 정보입니다. 구조는 `{id, name, order_number, product_name, option, order_status, paid_amount_krw, days_since_order, days_since_delivery}`입니다.
- `tickets.json`: 답변 전 문의 8개입니다. `{customer_id, subject, body}`만 저장하며 앱이 ID·상태·시각·이력을 생성합니다. 자연스러운 짧은 문의와 실제로 빠진 정보를 함께 둡니다.
- `evaluation.json`: 기대 분류와 확인할 사실을 적은 질문 30개입니다. 구조는 `{id, question, customer_id, expected_action, expected_document_ids, required_facts}`이며 마지막 2개에는 충돌 문서를 추가하는 `document_overrides`가 있습니다. 기대값이지 실행 결과는 아닙니다.

## 주문 정보의 범위

이번 화면은 고객별로 선택된 단일 상품 주문 1건만 다룹니다. 여러 주문 검색, 묶음 배송, 부분 반품 계산, 재고 조회, 택배사 조회, 결제 연동은 하지 않습니다. `SHOP-EX-1001` 형태의 주문 번호는 시연용 식별자입니다.

| 필드 | 의미 |
| --- | --- |
| `order_status` | `paid` 결제 완료, `preparing` 상품 준비 중, `shipped` 배송 중, `delivered` 배송 완료, `cancelled` 주문 취소 |
| `paid_amount_krw` | 해당 주문에 결제한 총액입니다. 상품 금액·배송비·할인 내역을 분리한 값이 아닙니다. |
| `days_since_order` | 문의 시점에서 주문 후 지난 달력 일수입니다. 영업일 수나 환불 승인 후 일수가 아닙니다. |
| `days_since_delivery` | 수령일을 0일로 센 경과 일수입니다. 배송 완료가 아닌 주문은 `null`입니다. |

프로필에는 착용·세탁 여부, 택 상태, 상품 사진, 옵션별 재고, 실측표, 케어 라벨, 소재 혼용률, 운송장, 택배 위치, 정확한 도착일, 결제 수단, 환불 승인 시점이 없습니다. AI가 채워 넣어서는 안 됩니다. 일반적인 추가 정보가 필요하면 고객에게 묻고, 시스템 확인이나 처리가 필요하면 담당자 확인 안건으로 남깁니다.

## 가상 매장의 공통 기준

| 항목 | FAQ 기준 |
| --- | --- |
| 일반 출고 | 재고가 있는 일반 상품은 결제 후 1~2영업일. 예약·입고 지연 상품은 별도 안내를 확인합니다. |
| 출고 후 배송 | 보통 1~3영업일. 특정 도착일은 보장하지 않습니다. |
| 교환·일반 반품 | 수령일을 0일로 센 7일째까지 접수. 외출 착용·세탁이 없고 상품 택을 유지해야 합니다. |
| 기본 배송비 | 할인 후 상품 금액 50,000원 이상 무료, 미만 3,000원입니다. |
| 제주 추가 비용 | 편도 3,000원입니다. 왕복 교환에는 6,000원을 추가합니다. |
| 변심 사이즈 교환 | 기본 왕복 배송비 6,000원이며 원하는 옵션의 재고 확인이 필요합니다. |
| 변심 전체 반품 | 최초 기본 배송비를 결제한 주문은 회수 3,000원, 기본 무료 배송 주문은 최초 배송비 포함 6,000원입니다. 제주 회수는 3,000원을 추가합니다. |
| 환불 기간 | 승인 후 카드 3~5영업일, 무통장입금 2~3영업일이 보통입니다. 결제 수단·승인 시점 확인 없이 입금일을 계산하지 않습니다. |
| 상담 확인 시간 | 평일 10:00~17:00, 점심 12:00~13:00 제외. 토요일·일요일·공휴일에는 문의만 남길 수 있습니다. |

이 수치들은 가상 매장의 동작을 확인하기 위해 정한 기준이며 법률 설명이 아닙니다. 불량·오배송, 예외 사유, 기간이 지난 반품은 담당자가 확인합니다. AI가 법적 권리나 보상 책임을 최종 판단하지 않습니다.

## 첫 화면에서 확인할 흐름

| 문의 | 기대 처리 |
| --- | --- |
| 주문한 옷 언제쯤 출발하나요? | `answer`: 결제 완료 상태와 일반 출고 기준을 안내합니다. |
| 바지 사이즈 교환하고 싶어요 | `clarify`: 착용·세탁 여부와 택 상태를 확인합니다. |
| 생각한 색이 아니라 반품하려고요 | `clarify`: 수령 시점은 프로필에서 확인하고 상품 상태를 묻습니다. |
| 검정 주문했는데 흰색이 왔어요 | `escalate`: 오배송 확인과 후속 처리는 담당자가 맡습니다. |
| 카드 결제가 두 번 됐어요 | `escalate`: 결제 내역을 담당자가 확인합니다. |
| 제주도도 무료 배송인가요? | `answer`: 기본 무료 배송과 제주 추가 비용을 구분합니다. |
| 취소했는데 돈이 아직 안 들어왔어요 | `clarify`: 결제 수단과 환불 승인 시점을 확인합니다. |
| 배송지 잘못 넣었어요 | `escalate`: 출고 여부를 확인한 뒤 담당자가 변경 요청을 처리합니다. |

AI는 검토할 답변 초안을 만들고 상담원이 첨삭해 확정합니다. 방향·키워드를 넣어 재생성해도 FAQ에 없는 사실이나 실제 처리 완료를 만들지 않습니다. 승인과 담당자 연결은 로컬 기록이며 고객 발송, 주문 취소, 주소 변경, 상품 수거, 재발송, 결제, 환불을 실행하지 않습니다.

## 평가 사용 방법

1. 질문에 지정된 고객 프로필과 FAQ를 함께 제공합니다. 주문의 상대 일수는 문의 시점의 값입니다. 현재 날짜와 비교해 사건 날짜를 새로 만들지 않습니다.
2. `answer`는 근거로 안내할 수 있다는 뜻입니다. 실제 작업 실행 성공을 뜻하지 않습니다. `clarify`는 고객에게 필요한 정보를 더 묻는 경우, `escalate`는 담당자 확인이나 실제 처리가 필요한 경우입니다.
3. `expected_document_ids`는 검색해야 할 출처 후보입니다. 문서 ID가 검색됐다는 것과 답변이 그 문서를 정확히 인용했다는 것은 별도입니다.
4. `required_facts`는 의미를 검토하는 기준입니다. 문장 전체 일치만 검사하지 말고 누락된 질문, 근거 없는 확정, 금지된 실행 주장을 확인합니다.
5. 29번은 기본 배송비 3,000원과 4,000원, 30번은 일반 반품 접수 기간 7일과 14일이 충돌하는 문서를 추가합니다. 해당 사례에만 `document_overrides`를 적용하고 다음 사례에는 기본 문서 집합으로 돌립니다. 두 충돌 문서는 기본 FAQ 10개에 포함하지 않습니다.

`uv run python -m desk.evaluate`로 JSON 구조와 참조를 검사할 수 있습니다. 실제 모델 평가는 `--live`와 키 설정이 필요하고 API 비용이 발생할 수 있습니다. 구조 검사가 통과해도 모델의 분류, 인용 정확성, 답변 내용이 검증된 것은 아닙니다. 실제 모델 호출, 모의 응답 검사, 사람의 문장 검토 결과를 구분해 기록해 주세요. 이 데이터에는 실행 합격률을 넣지 않았습니다.
